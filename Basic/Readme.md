Проверим синхронизацию.

### Порядок действий

**1. Создать новое пустое хранилище**

В Obsidian на телефоне — «Создать хранилище», любое имя. Не пытайтесь скопировать папку с компьютера вручную, клонирование сделает всё само.

**2. Поставить плагин**

Настройки → Сторонние плагины → выключить ограниченный режим → Обзор → Git → Установить → Включить.

**3. Вбить доступы**

В настройках плагина найдите раздел с логином и паролем для мобильных. Туда — имя пользователя на хостинге и тот же personal access token, что использовали на компьютере. SSH-ключи на мобильном не работают вообще, только токен.

**4. Клонировать**

Вызовите палитру команд (значок с иконкой команд или свайп) → найдите **Git: Clone an existing remote repo** → вставьте HTTPS-ссылку на репозиторий.

Плагин спросит про глубину клонирования (depth). Укажите **1** — скачается только последнее состояние без всей истории. Для телефона это принципиально: полная история может тянуться минутами и съедать память.

Ещё спросит, что делать с содержимым папки — выбирайте вариант, при котором конфигурация берётся из репозитория.

**5. Перезапустить плагин**

После клонирования — выключить и включить плагин в настройках, либо просто перезапустить Obsidian.

### Что стоит знать заранее

Разработчик прямо пишет, что мобильная версия нестабильна. Причина в том, что вместо настоящего git используется реализация на JavaScript. На тестовом хранилище в 3000 файлов проверка изменений во всей папке занимает около четырёх минут, хотя сами pull, push и commit проходят за секунды.

Отсюда практический вывод: **не включайте автокоммит по таймеру на телефоне**. Поставьте интервал в 0 и коммитьте вручную командой, когда закончили писать. Если хранилище большое — эффективнее ставить в индекс отдельные файлы через Source Control View и коммитить только их, а не всё сразу.

Ограничения мобильной версии, помимо скорости: не поддерживаются rebase и подмодули, размер репозитория ограничен памятью устройства.

### Рабочая привычка

Открыли Obsidian на телефоне → дождались, пока пройдёт pull (видно в строке состояния) → только потом пишете → закончили → вручную вызвали commit-and-sync. Если начать править до окончания pull, получите конфликт, а разбирать маркеры `<<<<<<<` на телефоне — то ещё удовольствие.

Если через неделю почувствуете, что мобильная часть больше мешает, чем помогает — рабочий компромисс: на телефоне только чтение и быстрые заметки через Remotely Save, а git оставить для десктопа.
